# 模型连接故障与修复验收

2026-11-03 用户报告：DeepSeek `/models` 返回两个模型，但连接测试显示“供应商响应格式不兼容”。线上日志中该次 `POST /api/models/test` 返回 502，持续 70.144 秒；这与原请求 70 秒期限吻合。原代码将 JSON 解码和响应读取错误合并，不能据此认定 Key 无效，也不能仅凭模型目录认定生成调用成功。

修复内容：连接测试采用明确的非思考参数，去掉不适用于 Chat Completions 的 `reasoning_effort: none`，输出预算 256 tokens；显式测试独立总期限 180 秒，前端显示等待时间并可停止。区分响应超时、中断、空体、HTML、无效 JSON、缺少消息和不完整回答。兼容带 BOM 的 JSON 与完整 SSE；不接受仅思考、空正文或截断回答作为成功。所有错误仅返回固定文案、代码及白名单元数据，不回传 Key 或供应商原始错误正文。普通非流式聊天也不再把空正文记录为成功回答。

官方依据：[思考模式参数](https://api-docs.deepseek.com/guides/thinking_mode/)、[请求保活机制](https://api-docs.deepseek.com/quick_start/rate_limit/)。官方说明排队期间非流式响应可能先发送空行。因此 70 秒失败可能与排队或传输延迟有关，具体原因仍须有效 Key 复测，不能由截图单独确定。

验证：云端模型、研究调用、上下文及持久化相关测试 68 项通过；本地模型测试 9 项通过；完整生产构建通过。网站版本 18 部署成功，环境修订仍为 3，未更换数据加密密钥。源码提交 `10be19ee500f2853ff6b55274dc26340e247b577`；部署 `appgdep_6ae9b21f40908191929d0ffdb4e9129d`。

部署后以全新访客和故意无效的测试 Key 实际请求两个供应商接口：模型目录与生成测试均准确返回供应商 HTTP 401，生成测试另有 `PROVIDER_RESPONSE`，证明当前云端能到达供应商并保留安全诊断。这不证明有效 Key 的推理成功。浏览器自动操作因无法可靠识别 Windows 当前浏览器 URL 而停止；未读取用户输入的 Key，未完成有效 Key 的线上生成验收，仍需在用户原页面再次点击测试并查看真实返回。
